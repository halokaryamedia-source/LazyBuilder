# Skill Catalog

Use this note for the current root skill inventory and ownership boundary.

## Canonical root skills

| Skill | Function |
|---|---|
| `development-brief` | mandatory front door for non-trivial repository/system Development; grounds goal, owner, minimal scope, acceptance criteria, proof budget |
| `build-production` | reusable production judgment for reference → Hunyuan → Blender → Minecraftize → schematic → Axiom work |

The root set is intentionally small.

## Relationship to product package

```text
root AGENTS / development-brief
→ decide work mode + semantic vs technical boundary
→ optional build-production
→ kits/lazy-builder/SKILL.md or AGENTS.md
→ smallest production / implementation owner
```

## Repository engineering is not a production skill

CI, repository verification, GitHub policy, dependency/test mechanics do not consume a product specialist slot.

## Skill freeze rule

Do not add/rename/split a root skill because:

- another file format or programming language appears;
- another Blender module exists;
- another block family appears;
- a one-off technical bug needs repair;
- another 3D provider exists in the market;
- a generic helper would be convenient.

Change the root skill set only when repeated work proves a distinct reusable semantic owner that current root policy, kit procedures, repository engineering, and existing skills cannot represent cleanly.
